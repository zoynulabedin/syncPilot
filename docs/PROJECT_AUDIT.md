# SyncPilot project audit

Date: 2026-11-03. Project: `D:\Clients-projects\syncPilot` (Windows 11). Branch: `main` at `f8a83f2` (same as `origin/main`), with today's changes uncommitted. Earlier audit dates and paths below refer to the original macOS development machine.

## Preservation and branch reconciliation

On 2026-11-01 the original working tree had a modified Compose file, new web config, untracked master specification and nested syncPilot directory. They were preserved. A patch and specification/startup archive were saved outside the repository on that machine (`~/.codex/backups/syncpilot-20261101`). No hard reset, clean, stash pop or force push was used.

Main (then `f049d9b`, the generic Shopify template) and the foundation (`bdcc5ee`) diverged. The implementation branch `codex/complete-syncpilot` was later merged into main in `d619e59`, keeping private distribution and PostgreSQL. That merge brought in the template's SQLite `Session` migration, which broke `prisma migrate deploy` on every PostgreSQL database, fresh or already migrated, and left a failed `_prisma_migrations` row; it was removed on 2026-11-03 (uncommitted). A database that ran deploy in that window refuses the nine migrations with P3009 until the row is marked rolled back (RUNBOOK, "P3009"); the earlier development database was not checked.

The nested `syncPilot` entry was tracked as a gitlink without a `.gitmodules` entry, so clones received an empty folder. It is now untracked and `/syncPilot/` is ignored; the local folder (empty on the current machine) was not deleted. It remains excluded from TypeScript, ESLint and the Docker context.
